After each run it rewrites its own engineering playbook, and soon its own weights. It keeps a lesson only if it does better on parts it has never seen.

why this matters

Software got its $200 founder. Hardware didn't.

AI collapsed the cost of starting a software company: one person, one subscription, a working product. Arlan built Nozomio after moving from Kazakhstan. Grok livestreamed a whole company run by one human managing agents. That revolution skipped hardware — because in hardware, a confident wrong answer doesn't throw an exception. It breaks.

Last night our own design optimizer crowned a part with negative drag as its best result. Nothing in the loop caught it. That's the problem FORGE exists to kill.

The vision we're living: a high-schooler with a $200/mo AI subscription doing what used to take $20M and a floor of engineers. Think Zipline, but at record speed: one node covering a continent with organ and medication delivery. One of us already used this exact loop to produce SQ-2, a 590 km/h electric quadcopter aimed at the 657.6 km/h world record: CNC 7075 hub, carbon spars, printed PA6-CF body, full-body CFD within 1.4 % of the design drag, 82 automated CAD checks, and independent audits that caught its own mistakes. Not a cylinder labeled "drone." A part list you could order.

Done Means Done

The agent writes its own numeric definition of done. The referee checks it — plus hidden loads the agent never saw. Drift gets caught, not reported.

Version N+1

Every run ends with a proposed lesson. A gate keeps it only if the score on unseen parts goes up. Rejections stay in the log — that's the honesty move.

Shared Brain

The playbook is the team's memory. Its value isn't how smart it reads — it's measured, on held-out parts, in pass rate and grams.

Receipts, not vibes

Referee validated against cantilever beam theory at 0.18% error (make selftest). Isolation is enforced by the build (make verify-isolation) — agent code that touches referee/hidden/ fails CI, and only the referee call path may read it. Every LLM call logged with dollar cost; hard budget cap per run.

What the playbook actually learned

v1: size arms for bending, gusset anything over ~50 mm, expect hidden overloads. v2: mesh-friendly geometry, verify mass and stress claims before claiming. Round 3's edit got rejected — dev score dropped. The gate caught it. That rejection is in the demo on purpose.

the judge's ask: show the comparison

Same prompt. Two different universes.

GPT-6 Astra, raw

  • Made a cylinder, called it a drone.
  • No material decision — plastic? metal? unsaid.
  • No manufacturability. No part numbers. No checks.
  • Thermal management, loads, aero behavior at speed: unexamined.
  • Reports success because nothing in the loop can say no.

FORGE's loop (SQ2 program)

  • CNC-milled frame — chosen because it's actually manufacturable.
  • Carbon tubes for structure, metal for props/internals, 3D-printed airfoil skin. Material per job.
  • Real COTS parts picked (motors, stack) — orderable today.
  • Stress margins on 21 load cases, full-body CFD (3.55 M cells, drag within 1.4 %), 590 km/h predicted, all in a dossier.
  • And in FORGE every claim meets a solver that can't be talked into anything.

Demo line: "The difference isn't the model. It's that ours is allowed to fail — in private, against physics — a hundred times before it tells you it's done."
